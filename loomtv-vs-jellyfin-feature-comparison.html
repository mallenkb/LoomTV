LoomTV vs Jellyfin, feature by feature

LoomTV is a focused video library and player that now also has a GUI-independent headless server boundary. Jellyfin remains a mature, continuously running media server with a much larger client and plugin ecosystem. This matrix compares what is implemented today—not what is merely planned.

LoomTV 1.0.101 source Jellyfin 10.11.x stable line 65 capabilities Core vs plugin distinctions included

The short answer

LoomTV covers the central movie, television, and anime experience surprisingly well. Jellyfin’s lead is not mainly basic playback; it is breadth, server maturity, remote reach, client coverage, and extensibility.

LoomTV leads

Focused household video UX

Dedicated anime treatment, temporary Guest profiles, profile export/import, rich per-profile preferences, MPV dual subtitles, and built-in skip-marker analysis are meaningful differentiators.

Rough parity

Core personal video library

Both cover movies and shows, metadata and artwork, search, resume state, Continue Watching, direct play, remuxing, transcoding, subtitles, and next-episode playback. LoomTV now adds headless catalog/media routes and server-side account policy.

Jellyfin leads

Media-server platform depth

Jellyfin adds headless hosting, remote access, web/TV/console clients, music, photos, books, Live TV/DVR, stronger hardware/HDR processing, plugins, APIs, and deeper administration.

Practical positioning

Choose LoomTV for a simpler, cinematic, local-first household video experience. Choose Jellyfin when the requirement is “serve every media type to every device, at home or away.” LoomTV does not yet replace Jellyfin as a general-purpose media server.

Highest-value gaps for a focused NAS-ready LoomTV

Full Jellyfin parity would dilute LoomTV's focused video and anime experience. These priorities first establish a dependable headless appliance, then widen client reach and deepen the enthusiast-video features where LoomTV can lead.

01. A real always-on server mode

The GUI-independent server, persistent state, scanning, direct delivery, HLS transcoding, admin API, and browser control plane now exist. Finish the shared desktop/headless database, profile/watch-state contract, restart recovery, and full NAS validation.

02. NAS-safe container deployment

Ship a non-root multi-architecture image, health checks, separate config/cache/media volumes, graceful shutdown, backups, and scan behavior that never erases an offline share.

03. Hosted web client and administration

Browser onboarding, library and scan controls, health, sessions, logs, backups, user policy, and transcode diagnostics are now available in headless administration. Finish browser library playback, profiles, progress, and capability negotiation.

04. Hardware/HDR pipeline

Make transcoding capability-aware and configurable across decoding, encoding, subtitle burn-in, HDR/HLG/Dolby Vision tone mapping, and client profiles.

05. TV and living-room clients

After the server contract is stable, Android TV/Fire TV plus one major smart-TV platform would change where LoomTV can be used more than another metadata provider.

06. Focused enthusiast features and API

Collections, versions, extras, NFO interoperability, and a stable public API deepen serious video libraries while preserving LoomTV's anime, dual-subtitle, skip-marker, and household-profile advantages.
