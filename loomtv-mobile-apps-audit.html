01 · Evidence

Thirteen observations across both mobile platforms.

This is a static implementation audit of the Expo, React Native, Android, and iOS source. No simulator, physical-device, runtime, visual, or network-condition testing was performed.

Revision, second pass. Every citation in this report was re-opened against the source. Four claims did not survive: the pairing copy had already been rewritten to the wording this report recommended, the Android proxy's thread pools are bounded rather than cached, Others selections already route to direct play, and the pairing screen already scrolls unconditionally. Those observations are corrected in place and marked. Three citations were wrong and are fixed: the DiceBear URL lives in App.tsx, the root holds 41 useState and 30 useRef hooks rather than "77 state hooks", and the LAN client has one shared fetch path with optional signal support on playback segments. Ratings were not raised to match, because nothing was measured.

Issues to address first
1

The Android release boundary does not fail closed.

TrustHigh-priority issue

Evidence. apps/mobile/android/app/build.gradle:100-116 assigns signingConfigs.debug to the release build. apps/mobile/android/app/src/main/AndroidManifest.xml:6-10 also contains storage, overlay, and system-settings permissions that are broader than the app-level allowlist.

Problem. EAS can inject production credentials, but the checked-in native release target is unsafe when built outside that path and current validation does not reject signing or permission drift.

Why it matters. A release process that depends on one build path rather than enforcing invariants can ship a wrongly signed artifact or expose unnecessary platform capabilities.

Quick win. Remove release-to-debug signing, block unneeded permissions through Expo configuration, add a release-manifest and certificate allowlist check, and make production builds stop when credentials are absent. Effort: Medium. Accept only artifacts whose signer and merged permissions match the release policy.
2

Playback causes repeated full-database snapshot writes.

EfficiencyHigh-priority issue

Evidence. apps/mobile/mobileOfflineCache.ts serializes the entire profiles, library, lists, and progress payload into one SQLite JSON row. apps/mobile/App.tsx:1540-1579 schedules a save after progress changes, while apps/mobile/App.tsx:2315-2321 updates progress every 15 seconds.

Problem. A small progress update rewrites the complete catalog snapshot, potentially including tens of megabytes of JSON.

Why it matters. The work scales with library size rather than the change size, increasing main-thread serialization, disk churn, battery use, and the chance of stutter during playback.

Quick win. Keep catalog snapshots immutable by revision, move progress and profile state into normalized incremental tables, batch writes on a slower cadence, and flush on background. Effort: Large. Measure SQLite bytes written per playback hour and offline-save p95 before and after.
3

Offline metadata is plaintext and Android backup is enabled.

TrustHigh-priority issue

Evidence. apps/mobile/mobileOfflineCache.ts persists profiles, viewing progress, lists, host identity, and catalog metadata as plaintext JSON. apps/mobile/android/app/src/main/AndroidManifest.xml:18 sets android:allowBackup="true" without app-specific extraction rules.

Problem. The cache is treated as local convenience data, but it contains household and viewing information that can enter device backups unless explicitly excluded.

Why it matters. A lost, restored, or inspected backup can reveal local media and behavior even when access credentials are protected separately in SecureStore.

Quick win. Encrypt sensitive rows with a platform-protected key, exclude the database from Android backup or define explicit backup rules, and document retention and deletion semantics. Effort: Medium. Validate backup contents on Android 11 and Android 12+ using the Android backup model.
4

LAN requests and stream preparation cannot reliably time out or cancel.

Error preventionHigh-priority issue

Evidence. apps/mobile/mobileLanClient.ts routes calls through a single shared fetch path, and getPlaybackSegments accepts an optional AbortSignal. The shared request path had no deadline, and most callers did not propagate cancellation. Pairing polling can run for roughly 65 seconds, and apps/mobile/App.tsx marks stream preparation as cancelled without aborting the underlying request or transcoding work.

Problem. A hung request can pin connection health checks, keep stale UI work alive, and create overlapping stream preparations after rapid navigation or track changes.

Why it matters. Office Wi-Fi, captive portals, address changes, and sleeping desktops are normal LAN conditions. Unbounded work makes the app feel frozen precisely when recovery should be clearest.

Quick win. Introduce one typed request client with operation-specific deadlines, AbortController propagation, lifecycle cancellation, and distinct timeout errors. Add server-side stream-session cancellation. Effort: Medium. Verify no request remains active after navigation, backgrounding, disconnect, or retry.
5

Others media leaks into core surfaces and opens the wrong flow.

Information architectureHigh-priority issue

Evidence. apps/mobile/mobileLibrary.ts:163 spreads grouped.others into allItems, and apps/mobile/App.tsx:1737-1750 builds Home's filter source, search, progress ownership, and item lookup from it. apps/mobile/App.tsx:6369-6373 seeds hero candidates from continue-watching, which can carry an Others title onto Home.

Problem. Others belongs only in its own folder, but core surfaces read from a collection that contains it.

Why it matters. Personal clips can be misclassified, surface on Home, and appear in core category searches next to library titles.

Verified as already correct. Selection routing is not affected: apps/mobile/App.tsx:3292 and 3345 both dispatch activeKind === 'others' ? playHomeItem : openDetailItem, so Others already plays directly instead of opening details. Home's has-content check at apps/mobile/App.tsx:6364 counts only anime, TV, and movies. Both were claimed as defects in the first pass and are not.

Quick win. Create explicit core-media and Others selectors, exclude Others from Home, anime, TV, movie, hero, My List, and global-core search sources, and dispatch Others selections directly to playback or image viewing. Effort: Medium. Add contract tests asserting zero Others IDs across every core surface.
6

Release evidence stops before production behavior.

Error preventionHigh-priority issue

Evidence. CI compiles Android debug and iOS simulator native targets, while apps/mobile/RELEASE_CHECKLIST.md still shows the physical-device matrix as pending. Existing tests are helper and source-contract tests rather than pairing, secure-transport, offline, and playback journeys on devices.

Problem. The most failure-prone boundaries, certificates, Bonjour discovery, office Wi-Fi, orientation, media decoding, backgrounding, and release signing, are not represented by recorded production-build evidence.

Why it matters. A passing source suite can coexist with a blank render, discovery failure, codec issue, or platform permission regression.

Quick win. Add signed release builds to CI, native transport tests, and a recorded device matrix for iPhone, iPad, Android phone, and Android tablet across offline, LAN, bad-network, and resume flows. Effort: Large. The release gate passes only when every checklist row has artifact-linked evidence.
7

The loopback bridge needs a tighter local threat boundary.

TrustMedium-priority issue

Evidence. apps/mobile/modules/loomtv-secure-transport/android/src/main/java/app/loomtv/securetransport/LoomTvSecureTransportModule.kt:171 exports stop(), and apps/mobile/mobileSecureTransport.ts:91 wraps it as stopSecureLanTransport — which App.tsx never calls. The loopback proxy has no per-session local secret.

Problem. The bridge stays up for the life of the process rather than for the life of a connection.

Verified as already correct. Thread pools are bounded, not unbounded: the same file uses newSingleThreadExecutor() to accept and newFixedThreadPool(8) to serve. The first pass claimed a cached, unbounded pool.

Why it matters. The port is ephemeral and remote authorization is still required, but defense in depth should limit local probing, denial of service, and stale resource use.

Quick win. Require a random per-start proxy secret, strip it before forwarding, cap concurrent connections, and stop the bridge on disconnect or inactive lifecycle unless active playback requires it. Effort: Medium. Add flood, malformed-request, stale-port, and teardown tests.
8

Pairing can become unreachable on small or enlarged layouts.

AccessibilityMedium-priority issue

Evidence. apps/mobile/App.tsx:3589-3600 sets scrollEnabled unconditionally, but gates bounces and automaticallyAdjustKeyboardInsets on keyboard visibility. The PIN keypad and several pairing actions do not expose a complete button-role, state, and announcement contract.

Problem. The reachability risk is narrower than first stated — scrolling always works — but the announcement contract on the only route into the app is still incomplete, and the keyboard-conditional inset handling is untested at large font scales.

Why it matters. Pairing is the only route into the app. Any accessibility failure there blocks the entire product.

Quick win. Add explicit roles and labels to keypad controls, announce errors and entered-digit count, and test at maximum supported font scale in portrait and landscape. Effort: Small. The first pass also asked to "always permit scrolling"; that is already the case.
10

One 6,775-line root owns too many product systems.

SimplicityMedium-priority issue

Evidence. apps/mobile/App.tsx is 6,775 lines holding 41 useState and 30 useRef hooks, and coordinates connection, pairing, profiles, catalog sync, offline restore, navigation, search, detail, playback, progress, settings, and modals.

Problem. Unrelated state transitions share one render and lifecycle boundary, making stale closures, accidental cross-surface behavior, and regression-safe changes harder to reason about.

Why it matters. The Others leak and repeated persistence work are examples of product rules crossing domains through shared root selectors and effects.

Quick win. Extract connection/session, catalog/offline, profile, navigation, and player controllers; move screens into feature modules; and enforce selectors at domain boundaries. Effort: Large. Track root render frequency and require feature-level integration tests before migration completes.
Needs verification
11

Instant offline imagery is not yet a guaranteed product contract.

System statusNeeds verification

Evidence. Metadata has an explicit SQLite snapshot, but artwork relies on the image component's opportunistic cache and profile avatars can resolve through a DiceBear internet URL built in apps/mobile/App.tsx:290.

Risk. A previously unseen or evicted image can remain blank offline even though the associated title metadata restores immediately.

Why verify. The local-first promise is perceived through posters and thumbnails, not only text. “Instant” must be measured across cold launch, eviction, and airplane mode.

Recommendation. Add an asset manifest, bounded prefetch queue, local avatar generation or desktop proxying, cache-health telemetry, and explicit placeholders. Measure cold and warm image-complete time at p50 and p95 on representative libraries.
Working well to preserve
9

Pairing guidance was rewritten before this pass.

CopyResolved in code

Evidence. apps/mobile/App.tsx:3735 reads: “On your desktop, open Settings > Network. Enter the HTTPS address and 6-digit PIN shown there. Do not use the address beginning with 127.0.0.1.”

Status. The first pass quoted an older string as current and recommended replacing it with the sentence that is already shipped. There is no defect here.

What remains. Only validation: a five-user manual-pairing test to confirm the current wording actually resolves discovery confusion.

12

The secure-LAN transport has a credible trust model.

TrustWorking well

Evidence. The custom Android and iOS modules pin the desktop certificate, bind the media bridge to loopback, reject redirects and remote cleartext traffic, constrain request sizes, and separate probing from authenticated transport.

Why it works. The mobile app can stream from a self-hosted desktop without disabling platform transport security globally or trusting arbitrary certificates.

What to preserve. Keep certificate pinning, origin normalization, HTTPS-only remote access, loopback-only cleartext exceptions, and the host-identity checks while tightening observation 7.

13

Playback and offline recovery are designed as first-class states.

Error recoveryWorking well

Evidence. The app includes playback retry classification, decoder and stream recovery, lifecycle-aware reconnect backoff, cached offline restore, accessibility actions for seeking, and a visible offline notice with retry and settings routes.

Why it works. Failures are modeled rather than reduced to a generic error, so users retain a path back to content when the desktop sleeps or the LAN changes.

What to preserve. Keep typed recovery states, adjustable seek actions, lifecycle-aware retries, and explicit offline status while adding deadlines and persistence improvements.

What works well

Secure local playback is thoughtfully built.

Certificate pinning, loopback transport, offline restore, and typed playback recovery create a strong foundation.

Primary issue

The build path and data path are not bounded enough.

Release signing drift, broad Android capabilities, full snapshot rewrites, and unbounded requests introduce avoidable risk.

Recommended action

Harden boundaries before adding features.

Fail-close releases, normalize offline persistence, isolate Others, and centralize request cancellation.

Expected outcome

Fast local startup with predictable recovery.

Users get consistent category behavior, lower disk and battery cost, and fewer stalls on difficult networks.

03 · Decision memo

Harden the release path first.
Then make local data truly incremental.

This pass should prioritize ship safety, predictable LAN recovery, and strict media-domain isolation. Visual polish and additional content features are deferred until production builds and device metrics prove the current foundation is stable.
