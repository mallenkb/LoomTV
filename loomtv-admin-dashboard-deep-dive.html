LoomTV / admin dashboard research

Every admin feature, explained and mapped to LoomTV

This report inventories the live Jellyfin admin dashboard, Plex's documented server controls, and LoomTV's current desktop and headless surfaces. It separates a useful feature from a useful default. LoomTV does not need every button Jellyfin or Plex has. It needs a clear home for the controls it already owns.

Research date: Aug 24, 2026Jellyfin live instance: 10.11.11Evidence confidence: medium

The right next step is one overview, not feature cloning.

Jellyfin's admin dashboard has 16 top-level areas and a strong server summary. Plex documents 15 server settings categories plus dashboards, sharing, and operations tools. LoomTV already has eight desktop settings sections and six headless admin pages. The gap is organization. Add one owner overview, then make each existing feature easy to reach.

LoomTV feature inventory

This is what LoomTV exposes today, separated between the desktop Settings experience and the headless `/admin` control plane.

Profiles

Personal profile, saved titles, My List, favorites, and profile-specific browsing. This is user experience configuration, not full server administration.

Library

Scan Library, automatic quick sync, quick sync, refresh metadata, full rescan, Movies/TV Shows/Anime/Other folders, local and NAS paths, unavailable-folder retention, grouping, sidebar order, database backup, and clear local data.

Network

Local network sharing, pairing and discovery, copyable addresses and share codes, Server Administration link, TLS-backed admin URL, shared-library discovery, six-digit PIN pairing, manual address, refresh, and disconnect.

Playback

Back and forward seek distances, display sleep timer, LibVLC native playback, mpv fallback, FFmpeg status, intro/outro detection, quick/full scan, pause/cancel/cleanup/rebuild analysis actions, manual markers, and exclusion lists.

Plugins

Official Stremio add-ons, remote HTTPS manifest review, explicit approval, installed add-on states, host configuration, profile access rules, provider failure counts, and retry/backoff status.

Metadata API Keys

TMDB, OMDb, Fanart, TVDB, TVmaze, Jikan, custom providers, show/hide/edit/delete, provider tests, OpenSubtitles credentials, languages, auto-download, artwork defaults, ratings, and fallback behaviour.

Theme

LoomTV visual preferences and loader options. This is the product's design surface rather than a full server branding editor.

About

Application identity, metadata and artwork sources, bundled media tools, third-party libraries, and dependency information.

Headless Overview

Health badge, server facts, library roots, connected clients, uptime, readiness checks, diagnostics, manage roots, and a next useful action.

Headless Library

Root cards for Movies, TV Shows, Anime, and Other video, add-folder dialog, server-mounted folder browser, library type, scan status, progress, and retry-safe unavailable roots.

Headless Sessions

Client, now playing, state, connection time, and bitrate in a table with refresh.

Headless Logs

Level, source, search, apply filters, refresh, paging, timestamp, source, and message columns.

Headless Backups

Start backup, optional destination, restore source, checksum validation, automatic pre-restore snapshot, atomic state replacement, session revocation, history, status, and location.

Headless Users

Owner unlock, add user, viewer/user/administrator role, permissions, root scope, allowed devices, concurrent session limit, disablement, session revocation, edit, and removal.

What to build from this research

Build in this order. The first steps improve the current experience without opening new product scope.

1

Make Overview the owner landing page

Reuse server health, setup state, library counts, scan progress, connected clients, recent events, and next action. Desktop and headless should read from the same state.

2

Explain each existing control at the point of use

Metadata keys say optional. Library folders say server path and NAS retry. Network says local versus remote. Playback says LibVLC first and what the fallback means.

3

Add a small operations layer

Recent activity, current jobs, scan errors, provider failures, backup health, and active sessions. Keep detailed Logs, Backups, and Sessions pages below it.

4

Separate credentials by purpose

Metadata provider keys, server API tokens, account sessions, and pairing codes should never appear as one generic key list.

5

Verify the risky states

Run keyboard-only setup, folder failure, provider rejection, scan retry, restore preview, session expiry, 200% zoom, and remote-access revoke checks before calling the admin dashboard complete.

6

Defer broad parity features

Live TV, DVR, DLNA, optimized versions, a general scheduler, and internet remote access need their own product decisions. Do not add empty navigation for them.

Sources, evidence, and limits

This report explains what was actually inspected and what remains a research or implementation question.

Report method: This document follows the current primary HTML Artifacts skill and the strict report-library requirements retained in the dated backup. The backup remains archived and is not registered as a second invokable skill. Theme rule: Lime is the only brand accent; green, amber, red, and blue are reserved for semantic status meanings. The external Plan Report page was checked, but Cloudflare Access exposed only its sign-in shell, so no content or skill provenance was inferred from it.

Evidence used

  • Live Jellyfin 10.11.11 dashboard DOM and admin routes: dashboard, general, branding, users, libraries, devices, activity, Live TV, DVR, plugins, networking, API keys, backups, logs, and scheduled tasks.
  • LoomTV desktop Settings and headless `/admin` source inspection.
  • Isolated LoomTV server setup state from the test data directory, without touching live media data.
  • Official Jellyfin and Plex administration documentation.

Limits

  • The local Plex web entry point stopped at its account sign-in gate. No credentials were entered, so Plex admin screens after sign-in are documented rather than live-observed.
  • The external Plan Report page was behind Cloudflare Access, so its findings were not treated as evidence.
  • No keyboard, screen-reader, responsive, error-recovery, physical NAS, casting, or performance test was run for this report.
  • Feature presence does not mean the same feature should be copied. Scope and security decisions remain LoomTV product decisions.
