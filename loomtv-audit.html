Issues to address first
1

Generated Android output can bypass the tracked security contract.

Build integrityCritical issue

Evidence. Tracked Expo configuration declares app.loomtv.mobile, disables global cleartext, adds a loopback-only network policy, and pins the Gradle distribution checksum. The ignored apps/mobile/android tree still declares com.anonymous.loomtvmobile, enables global cleartext, omits that policy and checksum, and signs release with the debug identity.

Problem. The reviewed configuration and the concrete native project disagree on application identity, transport policy, provenance, and release identity. A build that reuses stale generated output bypasses controls the tracked source appears to guarantee.

Why it matters. This reopens cleartext credential exposure and makes build results depend on an unreviewed local directory.

Quick win. Regenerate native output cleanly from tracked configuration, fail CI when the manifest, application ID, network policy, or wrapper checksum drifts, and keep publishing disabled until production signing is addressed.
2

Desktop artifacts can publish before identity is proven.

Release integrityHigh-priority issue

Evidence. build-installers.yml supplies signing/notary secrets to ordinary build jobs, treats missing credentials as a reason to disable signing, and lets tagged electron-builder --publish=always run before packaged verification. The stronger macOS release-verification script is not invoked, and the after-sign hook permits an ad-hoc fallback.

Problem. The release channel can receive artifacts whose publisher identity was never established by a mandatory post-package gate.

Why it matters. Update checksums identify bytes relative to metadata; they do not replace platform publisher identity if release infrastructure is compromised.

Deferred by request. Keep unsigned builds non-publishable. When signing/notarization resumes, separate build, sign, verify, and publish; protect secrets; require expected Team ID/publisher; and publish only after verification.
3

Boundary coverage proves source shape more often than behavior.

Recovery confidenceMedium-priority issue

Evidence. The repository now contains 53 test files and focused helper coverage for Range handling, TLS identity, and settings projections. However, securityBoundaryContracts.test.ts primarily reads source files and matches text, while release verification remains a test.todo.

Problem. Regex assertions can stay green when routing, token revocation, resource scope, process disposal, or publish order fails at runtime.

Why it matters. The repaired contracts cross HTTP, discovery, storage, FFmpeg, native transport, and release modules; source presence alone cannot prove the handoffs.

Quick win. Add adversarial HTTP and discovery integration tests, revocation and malformed-resource cases, fake-process lifecycle tests, and a packaged release fixture that fails on signer or ordering mismatch.
4

Mobile motion ignores the user’s reduced-motion preference.

AccessibilityMedium-priority issue

Evidence. Desktop styles and components honor reduced motion. Mobile ShimmerOverlay, PressableScale, and entrance helpers start repeating timing, spring, and scale animations without consulting AccessibilityInfo or an equivalent reduced-motion state.

Problem. Motion-heavy feedback remains active for users who explicitly request less animation.

Why it matters. Repeating shimmer and scale movement can create vestibular discomfort and makes accessibility behavior inconsistent across platforms.

Quick win. Centralize a mobile reduced-motion signal, render static loading/press states when enabled, and cover both initial preference and runtime preference changes.
5

Dependency risk is time-boxed, not eliminated.

Supply chainMedium-priority issue

Evidence. The full production audit now reports zero actionable advisories. It still relies on two exact waivers: React Router GHSA-qwww-vcr4-c8h2 until 2026-10-31 and Expo-tooling brace-expansion GHSA-mh99-v99m-4gvg until 2026-09-30.

Problem. The gate becomes risky again if compatible upstream fixes are not adopted before those dates or if the waivers broaden during maintenance.

Why it matters. Exact expiries are a good control only when ownership and upgrade work exist behind them.

Quick win. Assign each waiver, track the minimum fixed dependency chain, rehearse the Expo upgrade and native regeneration, and fail CI rather than extending an expired exception silently.
6

Four monoliths concentrate regression risk.

MaintainabilityMedium-priority issue

Evidence. Mobile App.tsx is about 6,192 lines, desktop VideoPlayer.tsx 3,109, mediaServer.ts 2,020, and desktop main.ts 1,759. Each mixes state transitions, policy, transport, lifecycle, and presentation concerns.

Problem. Security and performance fixes land in files with broad, interacting responsibilities, increasing review cost and the chance of accidental behavior coupling.

Why it matters. The new contracts are stronger, but future maintenance can erode them when ownership boundaries remain implicit.

Quick win. First lock behavioral contracts with integration tests, then extract transport, policy, lifecycle, and view-state modules incrementally without rewriting the working paths.
Needs verification
7

Pinned transport needs real-device confidentiality and load proof.

Transport trustNeeds verification

Evidence. Shared contracts now require HTTPS, saved connections retain a certificate fingerprint and host identity, mismatches require re-pairing, and native Swift/Kotlin modules implement pinned transport with loopback delivery.

Risk. Static inspection cannot establish that every pairing, refresh, metadata, media, redirect, and error path stays encrypted or that the native bridges maintain backpressure during long streams.

Why verify. Platform networking, generated manifests, proxy buffering, and certificate behavior only become authoritative on built devices.

Recommendation. Capture Android and iOS traffic, attempt forged mDNS/cert redirects, stream long media under constrained memory, and verify no credential-bearing cleartext or unbounded buffering.
8

Compact catalog adoption needs large-library proof.

ScalabilityNeeds verification

Evidence. Desktop and mobile now request revisioned compact indexes, fetch detail on demand, deduplicate requests, cap detail caches at 32 and 24 entries, and retain a legacy fallback. Index cards still carry summaries, artwork candidates, and one playback reference per episode.

Risk. The architecture removes full-detail hydration, but very long series still produce payload and reconciliation work proportional to episode count.

Why verify. Payload size, parse time, React reconciliation, and steady-state heap depend on real catalog shape and device capacity.

Recommendation. Benchmark 1k, 10k, and episode-heavy libraries; record bytes, cold/warm load, parse time, dropped frames, cache hit rate, and heap; then set regression budgets.
9

Accessible journeys still need runtime proof.

AccessibilityNeeds verification

Evidence. Source now labels address entry, uses “Use this desktop,” announces key errors/loading states, exposes semantic tabs and player controls, and gives desktop users reduced-motion and focus-visible behavior.

Risk. Focus order, hidden-control exposure, dynamic type, contrast, target size, resizing, and live-region timing cannot be established from JSX and CSS alone.

Why verify. DOM and React Native accessibility trees differ from source intent, especially in overlays and media controls.

Recommendation. Run keyboard, VoiceOver, and TalkBack journeys for pair, browse, play, profile switch, failure, and recovery; add automated axe coverage where applicable.

10

Network and authorization boundaries now fail closed.

Defense in depthWorking well

Evidence. LAN sessions use pinned HTTPS identity; mDNS mismatches re-pair; ping returns no credential; renderer authority is exact-origin/session scoped; settings are redacted and Owner-gated; profile identity comes from the verified token; profile creation requires Owner; revocation clears selection and unlock state.

Why it works. Authority now follows authenticated transport identity instead of request-controlled IDs, host names, loopback reachability, or raw settings objects.

What to preserve. Keep identity derivation centralized and make every future route declare origin, scope, profile policy, and revocation behavior.

11

Media paths and playback lifecycle are explicitly bounded.

Resource safetyWorking well

Evidence. Legacy raw subtitle paths are rejected; scoped opaque resources enforce type and containment; sidecar reads are asynchronous and capped at 8 MiB; embedded subtitle selection is typed. Ranges are strict, last-seen writes coalesce, stream credentials are short-lived, bindings dispose, and restart budgets are bounded.

Why it works. Routine playback no longer turns untrusted paths, malformed ranges, or segment traffic into unbounded main-process work.

Sync impact. These subtitle fixes authorize and limit file access; they do not rewrite subtitle timestamps or audio/video clocks, so audio synchronization should remain structurally unchanged.
