01 · Evidence

The high-priority boundary issues are closed.

Static verification covered Electron IPC, renderer metadata access, authenticated LAN mutations, SQLite persistence, and plugin contracts. Workspace TypeScript and targeted lint pass. Runtime traffic and UI scenarios were not exercised.

Issue to address next
1

Large composition files still need continued extraction.

Code structureMedium-priority issue

Evidence. New ownership modules now isolate HTTP operation contracts, provider transport, metadata refresh persistence, item-level catalog writes, and operation telemetry. The original composition and route files remain large.

Problem. The first extraction removes several cross-cutting responsibilities, but catalog, profile, playback, artwork, and administration dispatch are still colocated in the primary adapters.

Why it matters. The remaining size raises review cost even though the most error-prone boundary decisions now live in named modules.

Recommendation. Continue moving route families into thin controllers with explicit dependencies and typed results. This is now incremental architecture work, not a release-blocking contract defect.
Needs runtime verification
2

Offline and failure behavior needs scenario proof.

VerificationNeeds verification

Evidence. Local detail effects no longer fetch providers, incomplete metadata queues at startup and scan completion, refresh state persists per item, and artwork is warmed from SQLite-backed cache.

Risk. Static checks cannot prove perceived opening latency, provider outage behavior, app-restart recovery, or database migration behavior on an existing user library.

Recommendation. Smoke-test cold start, offline detail opening, scan completion, provider failure, retry cooldown, and app restart with a copied production library.
Implemented and working statically
3

LAN mutations now parse canonical schemas.

Runtime validationWorking well

Evidence. @loom-media-server/lan-protocol exports inferred request schemas for playback, profiles, artwork, progress, and track preferences. httpOperationRegistry.ts binds method, path, scope, owner, and parser, and mediaServer.ts consumes the typed result without coercive field parsing.

What to preserve. Add new LAN mutations through the registry and schema package first.

4

Renderer metadata uses one host gateway.

Provider architectureWorking well

Evidence. PluginDiscover.tsx and TVDetail.tsx have no direct provider fetch calls. Typed IPC sends discriminated OMDb, TMDB, or AniList requests to metadataProviderGateway.ts, where credentials, host allowlists, bounded responses, retries, and DNS protections remain in the main process.

What to preserve. Keep provider credentials and outbound transport outside renderer code.

5

Local details are database-first.

Offline behaviorWorking well

Evidence. Movie and TV detail pages no longer start automatic metadata refreshes when opened. A bounded background queue runs after scan completion and startup, while SQLite stores refresh timestamps and the last bounded error per item.

What to preserve. Keep manual refresh as an explicit user action and render local details from persisted state.

6

Metadata writes are incremental.

PersistenceWorking well

Evidence. saveLibraryItem performs one item upsert and reconciles only that title's seasons, episodes, and files in a transaction. Metadata refresh, provider availability, artwork application, and playback logo updates use it. Full replacement remains for scans and rebuilds.

What to preserve. Use catalog-wide replacement only when the catalog itself is being rebuilt.

7

Plugin declarations now come from TypeScript.

TypeScript qualityWorking well

Evidence. Public plugin contracts and local type exports are TypeScript sources, tsconfig.build.json emits package declarations to dist, and the declaration build passes.

What to preserve. Evolve public protocol contracts in TypeScript and regenerate declarations before packaging.

8

Provider operations emit privacy-safe structured events.

ObservabilityWorking well

Evidence. safeFetch records operation ID, duration, provider, retry count, result code, cache status, and allowlisted context. URLs, credentials, file paths, query values, and arbitrary context are not logged.

What to preserve. Extend the same event envelope to database and playback operations without widening the redaction allowlist casually.

Current structure

Five planes converge on the desktop host.

Renderer and mobile clients reach catalog, playback, profile, metadata, and plugin services through IPC or authenticated HTTP. SQLite is the durable local source.

Primary issue

Operations lack one canonical definition.

Contracts, routes, policies, decoders, and clients are spread across files, and some renderer pages call providers directly.

Recommended structure

One domain service, many thin adapters.

Define each operation once, validate at every boundary, call one service implementation, and project the result to IPC, local HTTP, LAN, or plugin consumers.

Expected outcome

Immediate details, safer changes, easier debugging.

Background enrichment fills SQLite, pages stay offline-first, and one request ID explains the complete path when an operation fails.
