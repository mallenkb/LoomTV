Findings and source evidence

1

Desktop admin is not part of the default startup

ArchitectureCriticalVisible

Evidence. The shipping build selects src/main.ts. Its unified server requires LOOMTV_UNIFIED_DESKTOP and an explicit data directory. The alternate canonical-main.ts contains the integrated server and admin startup, but is not the build entry.

apps/desktop/vite.main.config.ts:14
apps/desktop/src/main/unifiedDesktopServer.ts:39
apps/desktop/src/canonical-main.ts:363
README.md:34

Problem. The tray and README promise integrated administration while the default startup can only report that admin is unavailable. Recent URL and label changes did not restore that service.

Why it matters. People cannot reliably reach the administration workflow described by the product. This is a wiring and deployment-mode problem, not evidence that their data disappeared.

Action. Choose and document one production startup contract. Integrate administration with an explicit migration and rollback plan; do not blindly switch entry points or create a second database.

Acceptance. On a copy of an existing installation, open admin from a clean normal launch and verify the same users, folders and library. Verify upgrade and rollback before changing the default.

2

Offline download state can cross a profile boundary

Privacy and async stateCriticalVisible

Evidence. Switching between two valid profiles leaves the old download map visible until the replacement query resolves. Download completion merges into the current map without checking the host/profile that started it. Offline lookup uses only mediaId.

apps/mobile/useMobileDownloadsController.ts:33
apps/mobile/useMobileDownloadsController.ts:51
apps/mobile/useMobileDownloadsController.ts:75

Problem. An old profile operation can populate the new profile state. A failing replacement query can leave the previous map in place indefinitely.

Why it matters. Downloaded file references are profile-sensitive. A late completion can offer or select the wrong profile or host copy when media IDs overlap. End-to-end exposure depends on the selected title, but the state-isolation defect is direct.

Action. Key state by host and profile, clear it on identity changes, and guard every async completion with an identity generation. Check the stored download identity before returning an offline URI.

Acceptance. Switch profile and server during listing, download and removal. Late results must never enter the active map; offline playback must match the active host/profile.

3

TV resume mixes source time with transcoded stream time

Playback timelineCriticalInferred

Evidence. TV sends startSeconds to the playback plan. The server puts that value into FFmpeg input -ss. TV then applies the same startSeconds to the returned HLS player, and saves player.currentTime as source progress.

apps/tv/src/app.tsx:125
apps/tv/src/app.tsx:454
apps/tv/src/app.tsx:468
apps/server/src/media-service.js:397

Problem. Direct-file and newly generated HLS timelines share one code path without a source-time offset. The HLS source has already skipped the resume interval.

Why it matters. Resuming a transcoded title can seek twice, seek outside the current playlist, or save incorrect progress. The exact native HLS behavior needs device verification.

Action. Track source offset and stream-local position separately. Start a resume-offset HLS stream at local zero; translate progress and duration back into source coordinates.

Acceptance. Resume direct and HLS playback at 10 minutes, seek, exit, renew the lease and reopen. Both paths must retain the same source timestamp within tolerance.

4

TV lease renewal resumes paused video

Playback lifecycleMediumVisible

Evidence. The renewal callback replaces the source, restores a captured position and unconditionally calls player.play(). Cleanup cancels only the timer, not an already running renewal.

apps/tv/src/app.tsx:144

Problem. Renewal ignores pause intent and can finish after the player has been left. Position is also captured before the network request rather than at replacement.

Why it matters. A paused TV can start playing without user input. Slow renewals can rewind playback by the request duration.

Action. Preserve current playback intent and position at replacement, cancel or invalidate stale callbacks, and avoid source replacement when renewing authorization does not require it.

Acceptance. Renew while paused, playing, seeking and leaving the screen, with a delayed response. Pause and the current position must survive.

5

TV library merging duplicates canonical series

Catalog correctnessMediumVisible

Evidence. The server library endpoint includes canonical series. The TV client filters only matching episodes before appending grouped series from a second endpoint.

apps/tv/src/canonical-client.ts:121
apps/server/src/public-api.js:1295
apps/server/src/public-api.js:1304

Problem. Existing series are retained and then appended again, potentially with the same ID but different episode data.

Why it matters. TV can show duplicate titles and ambiguous item identity. The enriched series is also marked available regardless of episode availability.

Action. Merge by stable series ID or consume the canonical catalog endpoint. Prefer the episode-enriched record and derive availability from its visible episodes.

Acceptance. A canonical series with two episodes appears once; an offline-only series remains unavailable. Include legacy title-only series in the fixture.

6

Default aspect ratio never clears the VLC override

Desktop playbackMediumVisible

Evidence. The aspect effect returns early when the engine is libvlc and aspectMode is default, before calling setVideoAspect(null).

apps/desktop/src/components/VideoPlayer.tsx:2645

Problem. Selecting Default changes React state but leaves the previous native aspect override active.

Why it matters. This is the same reset-command omission previously fixed for Crop None, in a neighboring setting.

Action. Send the native null reset for Default. Keep CSS and native geometry consistent when a new session is created.

Acceptance. Change to 4:3 and 16:9, then Default, in windowed and fullscreen playback. The original aspect must return without restarting the video.

7

Download failure cleanup deletes the shared destination

Data integrityMediumVisible

Evidence. Downloads write directly into a deterministic host/profile/media directory with idempotent overwrite. A failure deletes the whole directory. The controller has no per-media in-flight guard.

apps/mobile/mobileDownloads.ts:114
apps/mobile/mobileDownloads.ts:124
apps/mobile/mobileDownloads.ts:131
apps/mobile/useMobileDownloadsController.ts:56

Problem. A retry or overlapping call can overwrite a valid copy, and one failed request can remove another request's completed data. SQLite failure after the file download also leaves an unregistered file.

Why it matters. The failure path is not isolated from previously saved content. UI disabling reduces ordinary overlap but does not make the persistence operation safe.

Action. Use a unique staging destination, deduplicate per identity/media, verify the completed file and commit metadata deliberately. Delete only staging files owned by the failed attempt.

Acceptance. Interrupt a download, retry it concurrently and fail the DB write. An existing valid download must survive and partial files must be recoverable or cleaned up.

8

Conditional catalog reads still rebuild the whole library

Server performanceMediumVisible

Evidence. Each catalog request filters all library items, serializes them and hashes the complete JSON before evaluating ETag or mediaId. listLibraryItems repeatedly scans the item list for each series.

apps/server/src/public-api.js:656
apps/server/src/public-api.js:1276
apps/server/src/public-catalog.js:6
apps/server/src/admin-service.js:1699

Problem. A 304 saves transfer bytes but not catalog computation. Single-title details also pay the full-catalog cost; series aggregation adds repeated work as the library grows.

Why it matters. Large libraries and multiple clients can spend substantial server CPU on unchanged reads. Actual latency has not been measured.

Action. Index episodes by series once per revision. Cache serialized projections by catalog revision and authorization/profile context, with invalidation on permission changes. Make detail lookups targeted.

Acceptance. Measure small and large catalogs, unchanged revalidation and parallel clients. Verify revocation and profile switching before returning cached data.

9

Global Space and hidden focus are deliberate accessibility tradeoffs

Interaction and accessibilityMediumVisible

Evidence. The recently requested Space handler runs before editable-target exclusion and consumes keydown/keyup. Player button focus outlines and rings are explicitly suppressed.

apps/desktop/src/components/VideoPlayer.tsx:3362
apps/desktop/src/index.css:2909

Problem. Typing a space into a player text field toggles playback instead. Keyboard users can move between buttons without a visible focus cue.

Why it matters. These behaviors follow the requested interaction choices, so they are not accidental regressions. They still make text entry and keyboard-only operation harder.

Action. Consider keeping universal Space for buttons and panels but excluding actual text entry. Consider showing focus only for keyboard navigation. Do not change these product choices without agreement.

Acceptance. Verify Space behavior in the marker editor inputs and navigate all player buttons without a mouse. Record an explicit decision for any retained limitation.

Startup and native smoothness still lack measured verification

Performance and maintainabilityMediumNeeds verification

Evidence. VLC initialization remains synchronous on Electron ready and the plugin cache remains disabled. The recent splash change removed artwork waits, not native initialization. Desktop VideoPlayer has 4,232 lines; mobile App has 6,603.

apps/desktop/src/main/libvlcWarmup.ts:240
apps/desktop/src/main/libvlcWarmup.ts:281
apps/desktop/src/main/libvlcRuntimeConfig.ts:5
apps/desktop/src/components/VideoPlayer.tsx:1
apps/mobile/App.tsx:1

Risk. There is no measured result in this audit proving launch, first frame, fullscreen or pause latency. Large coordinating components make ordering changes hard to review.

Why verify. Optimizing startup by deferring VLC can shift the wait onto first playback. Source-level checks alone cannot establish native animation quality.

Action. Measure process start, first window, usable page, VLC ready and first rendered frame separately. Extract session transitions and player input into focused units before further timing changes.

Acceptance. Compare cold/warm launches and an immediate Play click on representative macOS/Windows hardware. Require no regression in first-frame latency. Tests and profiling need separate approval.

11

Quiet mode hides all native VLC diagnostics

DiagnosticsMediumVisible

Evidence. Normal VLC instances receive --quiet. LOOMTV_DEBUG_LIBVLC=1 restores verbose output. Application playback error states still propagate.

apps/desktop/src/main/libvlcRuntimeConfig.ts:1

Problem. The previous timestamp-message change suppressed native logging rather than correcting timestamp conversion. It also suppresses unrelated native diagnostics.

Why it matters. The terminal is quieter, as requested, but intermittent decoder, audio or output problems lose detailed context unless the user relaunches in debug mode.

Action. Keep normal console output quiet but consider a bounded diagnostic capture with opt-in export and redaction. Label logging changes separately from decoder fixes.

Acceptance. Verify a failed open still reports a useful user error and an opt-in diagnostic report captures native detail without leaking media URLs or credentials.
