# Opus task: close product documentation and release truth

Start after migration, clients, casting, and sidecars are accepted. Read the
current code, manifests, workflows, release scripts, and handoff ledgers. Treat
them as the authority. This task changes documentation and release policy only.

## Outcome

Make every user, operator, contributor, release, NAS, browser, mobile,
television, migration, casting, subtitle, backup, and feature-status claim match
the implemented product and its evidence state.

## Steps

1. Verify every documented package name, command, route version, environment
   variable, file location, workflow selector, version rule, signing branch,
   artifact, and release-note requirement against the repository.
2. Rewrite desktop-relay, browser, mobile, NAS, migration, backup, casting,
   subtitle, and television descriptions to match the canonical design.
3. Remove stale percentages and unsupported completion claims. Label runtime,
   device, signing, browser, NAS, GPU, and accessibility evidence precisely.
4. Update the Opus ledger with the final changed-path and evidence inventory.

Completion criterion: documentation checks and workflow-policy checks pass.
Search finds no known stale product name, removed command, false fallback,
desktop-only topology, unsupported percentage, or planned feature described as
shipped. End with `PRODUCT_TRUTH_READY` only when no known documentation or
release-policy blocker remains.
