# LoomTV 2.0.21 release notes

libmpv playback works again in installed builds. Since 2.0.19 the packaged app shipped an outdated libmpv bridge and fell back to other engines. The bridge is now compiled from source at packaging time, and the package check fails if its version doesn't match.

Library cards no longer load full-size backdrops from providers other than TMDB. The app resizes its cached copy to the size the card draws, and keeps smaller TMDB renditions between launches instead of fetching them again. On a test library, decoded artwork on Home fell from 19.5 to 5.5 megapixels and main process memory from about 210 to 155-160 MB.

The macOS download is 211 MB smaller. Each Mac package now carries only its own architecture's FFmpeg, FFprobe and fpcalc, drops the other architecture's native modules and unused build files, and ships only the English Chromium locale.

Security: release builds set Electron fuses in the packaging config, and the package check reads them from the built app. A default-deny permission policy allows only fullscreen and clipboard writes, and denies devices and screen capture. YouTube and Vimeo links open in their embed players, and links that are not a single video show an error.

The window appears sooner because LibVLC starts 2 seconds after the window shows instead of before it. When two native engines fail, playback moves to the browser player instead of alternating between them.

This release publishes Electron desktop installers for macOS, Windows, and Linux. It does not publish Tauri or mobile binaries.
