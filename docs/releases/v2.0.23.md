# LoomTV 2.0.23 release notes

libmpv uses one hardware decoder thread to reduce memory during 4K playback. Software decoding keeps its existing thread behavior, and video rendering quality stays unchanged.

Closing mpv playback now releases its renderer, OpenGL context, and Retina drawable. Failed and duplicate renderer setup paths also clean up. The render bridge lifecycle test covers repeated close and reopen, failed attachment, and decoder settings on the built-in display without activating its test window.

Chromium no longer builds large backdrop-blur surfaces for paused native playback controls. The player controls and side panel keep bounded layers, reducing GPU memory use.

Switching or editing profiles from inside the app leaves the side navigation available while keeping the page behind the gate inaccessible. Startup and locked profile gates still cover the full window. Profile gate controls use the shared button style, settings disclosure cards apply the same background across their headers and content, and the update action uses the primary button style.
