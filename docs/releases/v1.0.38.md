# Loom Media Server 1.0.38 Release Notes

Loom Media Server 1.0.38 fixes the macOS restart-to-update path after the app rename.

## Fixed

- Repackages the macOS updater ZIP with the legacy `LoomTV.app` outer directory so installed 1.0.36 clients can apply it, while keeping the current Loom Media Server name and bundle identity inside the app.
- Validates and extracts the downloaded archive before closing the running app, allowing malformed or inaccessible updates to report an error without quitting.
- Replaces the exact app bundle that initiated the update instead of creating a second bundle under a new product name.
- Verifies that the updated app relaunches and restores the previous bundle if installation or relaunch fails.
- Forces the already-drained app process to exit if a lingering handle would otherwise leave the installer waiting indefinitely.

## Verification

- Static inspection covered the retained 1.0.36 helper logs, the downloaded 1.0.37 archive layout, updater control flow, and release packaging identity.
- Runtime, packaged-update, and visual verification were not performed.
