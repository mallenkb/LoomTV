# LoomTV 1.0.59 Desktop Release Notes

LoomTV 1.0.59 is a desktop-only release that completes the profile experience across the macOS, Windows, and Linux apps. It adds full profile management, PIN and Kids-profile controls, personal lists and preferences, secure profile-aware local-network delivery, profile transfer, content-rating metadata, and stricter authorization around library and server administration.

## Profile selection and management

- Adds a full-window **Who's watching?** experience at startup when a profile must be selected.
- Keeps the app shell mounted when the profile picker is reopened, allowing the picker to behave as an overlay during an active session.
- Adds a visible active-profile treatment so the currently selected viewer is immediately identifiable.
- Adds a Back action when the profile picker is opened from inside the app.
- Adds an owner-only **Edit Profiles** mode.
- Adds profile creation for Standard and Kids viewers.
- Adds profile editing for names, avatars, colors, profile type, PIN, automatic sign-in, and Kids restrictions.
- Adds permanent profile deletion with an explicit confirmation step.
- Prevents deletion or type conversion of the Owner profile.
- Adds left/right profile reordering and persists the chosen order.
- Adds keyboard spatial navigation across visible profile controls with the arrow keys.
- Restores keyboard focus to the previously selected profile after closing an editor or PIN prompt.
- Adds profile switching from the sidebar even when only one permanent profile currently exists.
- Prompts before switching profiles while media is playing, stops playback safely, saves the current position, and flushes pending progress writes before the switch.
- Rehydrates the library, progress, preferences, and personal lists for the newly selected profile using a generation guard so stale asynchronous responses cannot overwrite the new viewer's state.
- Adds explicit profile lock behavior that stops playback, flushes progress, clears personal state from the renderer, and returns to profile selection.
- Adds automatic sign-in for eligible PIN-free profiles and disables it for protected or temporary Guest profiles.
- Adds a dedicated Profiles section in Settings showing the active avatar, profile type, switch/manage action, lock action, automatic sign-in control, PIN setup, and PIN removal.
- Restricts profile administration to an Owner session that has actually been authorized, rather than merely checking that an Owner record exists.

## Profile avatars and visual identity

- Replaces the eight generated weave-and-initial avatars with twelve DiceBear Glyphs avatar choices.
- Adds eight profile color choices with simpler, solid-color avatar rendering.
- Adds support for uploading a custom PNG, JPEG, or WebP profile image from disk.
- Validates uploaded profile images as bounded data URLs before saving or importing them.
- Migrates existing `weave-01` through `weave-08` avatar keys to their matching `glyph-01` through `glyph-08` variants.
- Adds DiceBear Glyphs attribution to the in-app license list.
- Bundles the DiceBear Glyphs CC BY 4.0 license in Forge packages and electron-builder installers.

## PIN protection and recovery

- Adds a reusable four-box PIN input with numeric filtering, paste support, Backspace behavior, left/right navigation, focus management, one-time-code hints, and accessible digit labels.
- Adds an on-screen numeric PIN keypad to the profile unlock screen.
- Accepts keyboard number entry and Backspace on the unlock screen when focus is not inside another form field.
- Requires exactly four digits for new or changed profile PINs.
- Turns off automatic sign-in when a profile is protected by a PIN.
- Requires the active protected profile to be unlocked before its PIN can be changed.
- Prevents Guest profiles from receiving PINs.
- Keeps PIN verification backed by unique scrypt credentials and constant-shape verification coverage.
- Adds a **Forgot Owner PIN?** recovery flow guarded by typing `RESET`.
- Resets only the Owner's personal data, viewing history, preferences, lists, restrictions, and credentials while preserving the media library, server configuration, paired devices, and other profiles.
- Recreates the Owner with a new identifier during recovery so stale device selections and personal rows cannot remain attached to the reset account.

## Kids profiles and content restrictions

- Adds Kids-profile controls for ratings country, maximum permitted age, unrated-content access, and allowed library folders.
- Supports content-rating policies for the United States, United Kingdom, Canada, and Australia.
- Normalizes recognized movie and television certifications into a minimum-age model.
- Maps Jikan anime ratings into the same minimum-age model.
- Merges ratings from multiple metadata providers conservatively, keeping the most restrictive recognized certification for each country.
- Stores content ratings on library items and preserves them through scans, metadata refreshes, and database reloads.
- Fetches TMDB movie release certifications and television content ratings.
- Reads OMDb rated values and Jikan anime ratings where available.
- Treats a Kids profile with no maximum age as unable to access content until configuration is completed.
- Allows owners to decide whether unrated media is visible to a Kids profile.
- Allows Kids access to all library roots or a selected subset of current configured roots.
- Canonicalizes and validates allowed folders against existing library roots to prevent arbitrary-path restrictions from being stored.
- Filters movies, television, and anime before the library reaches the renderer.
- Applies the same profile policy to desktop playback, media probing, thumbnails, artwork, subtitles, direct streams, transcoded streams, and HLS sessions.
- Invalidates HLS access when the selected profile or selection revision changes during a session.
- Hides metadata artwork editing and other Owner-only library administration controls from non-Owner profiles.
- Prevents non-Owner profiles from triggering automatic library scans or owner-level local analysis work.

## Watchlist, Favorites, and personal state

- Adds per-profile Watchlist and Favorites collections.
- Adds Favorite and Watchlist buttons to movie detail pages.
- Adds Favorite and Watchlist buttons to television and anime detail pages.
- Adds dedicated Watchlist and Favorites rails to Home when those lists contain items available to the active profile.
- Orders personal-list entries by most recently added.
- Limits each Home list rail to the first 20 resolved library items.
- Keeps progress, watched state, audio/subtitle preferences, theme, navigation order, playback controls, lists, and restrictions isolated by profile.
- Adds expected-profile identifiers and selection generations to profile-sensitive writes so delayed writes cannot land on a different viewer after a switch.
- Adds durable profile selection revisions independent of the current selection row, preserving stale-session detection even after a profile is deleted or locked.

## Per-profile preferences

- Moves theme mode, accent color, dark-theme choice, loader style, sidebar navigation order, skip-back duration, and skip-forward duration into profile preferences.
- Retains legacy global values as a compatibility fallback while each profile adopts its own settings.
- Migrates existing personalizable global settings onto the Owner profile and removes those keys from shared app settings after migration.
- Reloads theme and sidebar order whenever the active profile changes.
- Saves theme changes, navigation order, and playback skip intervals against the expected active profile.
- Keeps server-wide scan, metadata, network, database, and analysis settings under Owner control.
- Shows only Profiles, Playback, Theme, and About settings to non-Owner profiles.
- Hides server-wide playback-analysis controls from non-Owner profiles while retaining personal playback controls.
- Adds an explicit **Save playback settings** action.
- Renames accent presets from internal brand-style names to Orange, Netflix, Paramount, Disney, and Twitch while preserving their existing color values.

## Profile export and import

- Adds Owner-authorized profile export to a versioned `loomtv.profile.v1` JSON file.
- Exports profile metadata, progress, playback track preferences, personal preferences, Kids restrictions, Watchlist, and Favorites.
- Excludes Guest profiles from export.
- Adds profile import through a native file picker.
- Validates export format, timestamps, names, profile types, avatars, colors, progress values, track scopes, preferences, restrictions, folder lists, and personal-list entries before import.
- Applies bounded entry limits to protect against oversized or malformed profile files.
- Imports only progress paths that still exist in the current library.
- Imports only list entries whose media identifiers still exist in the current library.
- Reports imported and skipped progress/list counts after import.
- Imports Owner exports as a new Standard or Kids profile rather than creating a second Owner.
- Runs import in a database transaction so partial profiles are not left behind after a failure.

## Local-network profile support

- Advertises profile API version 1 and capabilities for profiles, PINs, Kids restrictions, profile preferences, and profile lists.
- Adds LAN endpoints to list profiles, read active selection, select/unlock a profile, lock a profile, and configure automatic sign-in.
- Adds LAN endpoints to read and update profile preferences.
- Adds LAN endpoints to read, add, and remove Watchlist and Favorite entries.
- Assigns explicit catalog or playback scopes to every new profile endpoint.
- Returns an empty bootstrap library to profile-aware clients until they select a profile, preventing the full catalog from leaking before authorization.
- Keeps compatibility behavior for older clients that do not advertise profile API support.
- Binds signed artwork, thumbnail, subtitle, and stream URLs to device ID, profile ID, and profile selection revision.
- Rejects stale signed resources after a profile switch, lock, deletion, or selection revision change.
- Requires an explicit current profile for profile-aware progress and playback-track preference reads and writes.
- Validates selection revisions on remote mutations to reject writes from stale clients.
- Filters the LAN library through the same Kids content policy used by the desktop renderer.
- Adds profile-aware HLS session bindings and rechecks authorization throughout segmented playback.
- Clears temporary Guest profiles during desktop startup/shutdown cleanup and records Guest as a distinct database profile type.

## Desktop authorization and security

- Requires an active authorized profile before returning the renderer library.
- Adds profile-aware path authorization before probing media, reading thumbnails, serving local images, opening subtitles, or starting playback.
- Requires Owner authorization for shared settings changes, metadata credentials, library administration, artwork management, skip-marker administration, local analysis controls, database backup, and database reset.
- Replaces direct settings reads with a renderer-safe settings projection.
- Preserves selection revisions when profile rows and their device selections are removed.
- Advances affected device revisions before deleting or resetting a selected profile.
- Validates profile imports and custom avatars before any database writes.
- Adds tests for content-rating normalization, conservative rating merges, PIN credential uniqueness, PIN verification behavior, profile isolation, Guest cleanup, Owner reset, and the expanded migration ledger.

## Playback and progress changes

- Always enables next-episode autoplay and keeps the existing countdown behavior.
- Removes the in-player **Autoplay next episode** toggle.
- Removes renderer `localStorage` persistence for audio and subtitle track choices.
- Stores track preferences only in the active profile's database-backed state.
- Fetches profile track preferences asynchronously and saves them with the expected profile identifier.
- Removes legacy media-level `lastPlayed` fallback from Continue Watching ordering.
- Derives Continue Watching activity exclusively from profile-specific progress timestamps.
- Stops persisting library-level `lastPlayed` values and removes them from loaded renderer items.
- Preserves progress migration safety by attaching imported progress to the expected active profile.

## Database and migration changes

- Adds profile selection ledger migration version 3.
- Adds Guest profile-type migration version 4 and rebuilds the profile table with `guest` as an explicit allowed type.
- Adds Glyph avatar migration version 5.
- Adds automatic-sign-in migration version 6 for eligible PIN-free permanent profiles.
- Adds `content_ratings_json` to media-item persistence.
- Migrates existing personalizable app settings to the Owner profile.
- Removes migrated personal keys from shared settings to prevent cross-profile leakage.
- Keeps all new migrations idempotent and verifies foreign-key integrity after the Guest profile table rebuild.
- Updates database reset to clear selection revisions and create/select a fresh Glyph-based Owner profile.

## Removed or replaced behavior

- Removes the old weave-and-initial profile avatar renderer and its eight-avatar limit.
- Removes the in-player next-episode autoplay preference; autoplay is now consistently enabled.
- Removes browser-local audio/subtitle preference storage in favor of profile database storage.
- Removes shared global ownership of theme, sidebar order, and playback skip intervals in favor of per-profile values.
- Removes library-item `lastPlayed` as a Continue Watching fallback and durable library field.
- Removes unrestricted renderer access to media paths and replaces it with active-profile content authorization.
- Removes non-Owner access to library, network, metadata, database, artwork, and local-analysis administration.
- Removes unbound LAN artwork, subtitle, thumbnail, stream, and HLS delivery for profile-aware clients and replaces it with selection-bound signed access.
- Removes automatic fallback to an unselected desktop library; an active profile is now required before personal content is delivered.
- Replaces internal accent names Sunflare, Emberline, Deepwave, Aqualume, and Nightbloom with user-facing service/color names.
