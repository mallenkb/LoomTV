01 · Evidence

Five API planes, three strong boundaries, one ownership problem.

Static inspection traced Electron IPC, local renderer HTTP, authenticated LAN HTTP, external metadata services, and Stremio/plugin contracts. No runtime traffic was captured.

Issues to address first
1

LAN request bodies are not contract-validated.

Runtime validationHigh-priority issue

Evidence. mediaServer.ts has 17 readJsonBody(req) call sites. The parser only proves that JSON is an object; handlers then coerce fields with String, Number, Boolean, and type assertions.

Problem. IPC arguments are Zod-validated, but equivalent LAN mutations do not share request schemas. Invalid values can silently become defaults, such as a non-boolean value becoming true.

Why it matters. Desktop, browser, and mobile behavior can diverge, and future fields can cross a network boundary without a reliable runtime contract.

Quick win. Define request and response schemas in @loom-media-server/lan-protocol, then parse every route before calling a service.
2

Renderer pages bypass the provider gateway.

Provider architectureHigh-priority issue

Evidence. PluginDiscover.tsx calls OMDb, TMDB, and AniList directly. TVDetail.tsx also calls AniList directly, while main-process provider modules use safeFetch.

Problem. Those calls skip centralized host allowlists, DNS rebinding protection, bounded responses, retries, durable caching, and consistent error mapping. TMDB and OMDb credentials also enter renderer code paths.

Why it matters. Discover and local details do not share one reliability, security, or offline model.

Quick win. Move Discover and cast enrichment behind one main-process metadata service and expose typed operations over IPC and LAN.
3

The transport layer is represented in several places.

Contract ownershipHigh-priority issue

Evidence. The code defines 111 IPC invoke channels, 5 IPC events, at least 45 literal HTTP route branches, a LAN route policy, a remote-client allowlist, a mobile client, preload bindings, desktop decoders, and shared protocol types.

Problem. A route can require coordinated edits across policy, server dispatch, client wrappers, schemas, and fallback paths. These are manually synchronized instead of derived from one operation registry.

Why it matters. Missing one representation can create an authorization mismatch, stale client, or silent fallback to the legacy full-library transport.

Quick win. Introduce a typed operation registry containing method, path or channel, scope, request schema, response schema, and handler ownership.
4

Core orchestration files are change hotspots.

Code structureMedium-priority issue

Evidence. mediaServer.ts is 1,999 lines, main.ts 1,993, desktopApi.ts 1,911, ipcHandlers.ts 1,232, and officialMetadataService.ts 1,217.

Problem. Authentication, routing, transport adaptation, domain orchestration, and response formatting remain adjacent in large files even though useful helpers and repositories have been extracted.

Why it matters. Review scope grows with each feature, local reasoning becomes expensive, and unrelated operations can regress together.

Quick win. Split by operation family: catalog, profiles, playback, artwork, metadata, and administration. Keep the composition root declarative.
5

Metadata completion is triggered by opening details.

Offline behaviorMedium-priority issue

Evidence. Movie and TV detail pages call refreshIncompleteMetadata after rendering when provider ratings are missing. The service then fetches, saves the library, caches artwork, and rehydrates the item.

Problem. The database does persist summaries, episodes, cast, providers, artwork references, and IDs, but incomplete records are repaired in the user-facing detail flow.

Why it matters. Users see placeholders for several seconds, and offline use preserves whatever completeness existed before the page was opened.

Quick win. Queue incomplete metadata at scan completion and startup, record freshness and last error per item, and let details read stored state immediately.
6

Library persistence rewrites the entire catalog.

PersistenceMedium-priority issue

Evidence. saveLibrary opens a transaction, deletes episode files, episodes, seasons, media items, folders, and scan cache, then inserts every current row again.

Problem. Atomicity protects correctness, but one metadata refresh or artwork change can produce catalog-wide write amplification and revision churn.

Why it matters. The cost and lock duration scale with the whole library, not the changed item.

Quick win. Add item-level upserts with child-row reconciliation; reserve full replacement for rebuild and migration flows.
7

The plugin protocol has parallel JavaScript and declaration sources.

TypeScript qualityMedium-priority issue

Evidence. @loom-media-server/plugin-protocol ships handwritten .mjs implementations beside handwritten .d.ts declarations, while the LAN protocol derives several types from Zod schemas.

Problem. Runtime behavior and TypeScript declarations can drift because neither is generated from the other.

Why it matters. A trust-boundary package should make invalid divergence mechanically difficult.

Quick win. Author the package in TypeScript, generate declarations, and keep JSON Schema compatibility tests at the boundary.
Needs verification
8

Operational diagnosis is mostly console-based.

ObservabilityNeeds verification

Evidence. Server and metadata failures use route-specific console.error and console.warn calls. Static inspection found no request correlation ID, provider timing field, cache outcome, or structured error envelope shared across planes.

Risk. A slow detail page can require reconstructing IPC, provider, database, and renderer events manually.

Recommendation. Add privacy-safe structured events with operation ID, duration, cache status, provider, retry count, result code, and redacted context.
Working well to preserve
9

Security boundaries are explicit and unusually careful.

SecurityWorking well

Evidence. IPC verifies trusted senders and validates arguments. LAN access uses TLS, short-lived access tokens, hashed refresh credentials, device scopes, profile selection revisions, rate-limited pairing, signed resource URLs, and timing-safe comparisons.

What to preserve. Keep route scope decisions separate from handler business logic, and keep local renderer credentials unavailable through public HTTP.

10

Provider transport is hardened.

External APIsWorking well

Evidence. safeFetch requires HTTPS, supports host allowlists, rejects non-global addresses, pins the validated DNS result, strips secrets on cross-origin redirects, bounds response size and time, and retries idempotent failures.

What to preserve. Make this gateway mandatory for every external metadata and artwork request.

11

The stored catalog already supports fast offline details.

Data modelWorking well

Evidence. SQLite stores title, summary, provider ratings, streaming providers, origin platform, cast, provider IDs, seasons, episode summaries and stills, artwork candidates, and local technical metadata. Catalog index and item routes use revision-aware ETags.

What to preserve. Keep SQLite as the source for local detail rendering. Treat providers as asynchronous refresh inputs, not page-load dependencies.

Current structure

Five planes converge on the desktop host.

Renderer and mobile clients reach catalog, playback, profile, metadata, and plugin services through IPC or authenticated HTTP. SQLite is the durable local source.

Primary issue

Operations lack one canonical definition.

Contracts, routes, policies, decoders, and clients are spread across files, and some renderer pages call providers directly.

Recommended structure

One domain service, many thin adapters.

Define each operation once, validate at every boundary, call one service implementation, and project the result to IPC, local HTTP, LAN, or plugin consumers.

Expected outcome

Immediate details, safer changes, easier debugging.

Background enrichment fills SQLite, pages stay offline-first, and one request ID explains the complete path when an operation fails.

03 · Decision memo

Make providers asynchronous.
Make contracts canonical.

The fastest path to 9.0 is architectural consolidation, not another API. Keep the existing security and SQLite foundations, then make every UI and client go through one validated operation layer.

Overall6.8 → 9.0
  • Adopt one operation registry for IPC and HTTP. Fixes 1, 3
  • Move every external provider call behind the host gateway. Fixes 2, 5
  • Split boundary files by domain operation family. Fix 4
A 9.0 rating requires runtime contract tests, failure injection, performance measurements, and an offline scenario matrix.
Contracts6.4 → 9.0
  • Derive request and response types from runtime schemas.
  • Generate route policy, client bindings, and API documentation from the registry.
  • Remove coercive parsing from network handlers.
Modularity5.9 → 9.0
  • Make route modules thin adapters over domain services.
  • Keep main.ts as composition only.
  • Replace whole-library saves with targeted repository operations.
Security8.6 → 9.0
  • Preserve trusted-sender IPC, scoped LAN auth, TLS, resource capabilities, and safeFetch.
  • Apply schemas before authorization-sensitive service calls.
  • Add boundary-focused contract and abuse-case verification.
Step 01Freeze the inventoryList every IPC and HTTP operation, owner, scope, schema, client, and legacy fallback.
Step 02Centralize contractsCreate shared runtime schemas and generate types, route policy, and thin client bindings.
Step 03Centralize providersRoute Discover, local details, cast, provider availability, and artwork through the same host service.
Step 04Make metadata offline-firstPersist freshness, queue enrichment after scans, and render only stored detail state.
Step 05Split and instrumentExtract domain route modules, add targeted upserts, and emit correlated operation events.
9.0 gate. One registry describes every public operation; every untrusted payload is parsed by a runtime schema; no renderer page contacts metadata providers directly; a fully enriched item opens with no network; and one correlation ID explains an operation across adapter, service, provider, and database logs.
