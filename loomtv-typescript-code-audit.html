Issues to address first
4

Type claims replace validation at trust boundaries.

Boundary safetyHigh-priority issue

Evidence. apps/mobile/App.tsx:745-754 returns {} as T for an empty successful response and JSON.parse(text) as T otherwise. The same pattern appears in TMDB, Jikan, AniList, TVmaze, four SQLite repositories, and the generic IPC wrappers at ipcHandlers.ts:303-305 and 328-340.

Problem. Generic return types and IPC contracts describe the desired shape to the compiler, but they do not inspect runtime values. A malformed provider response, stale database row, corrupted secure-store value, or mismatched renderer call can therefore enter trusted code with a false type.

Why it matters. Failures occur far from the boundary, often as missing-property crashes or incorrect defaults, which makes recovery and diagnosis harder. IPC options that eventually reach playback and filesystem code deserve especially explicit validation even when sender identity is checked.

Quick win. Add small decoders that accept unknown and return validated domain values. Start with pairing/session payloads, metadata providers, and IPC channels that touch settings, paths, or native playback. Effort: Large. Done means invalid fixtures fail at the boundary with a named error and no unchecked JSON.parse(...) as T remains on those paths.
2

Ownership sprawl obscures ordinary control flow.

ArchitectureMedium-priority issue

Evidence. Production source contains 565 type assertions, concentrated in database adapters, desktopApi.ts, metadata clients, and App.tsx. MediaItem is independently defined for main metadata, desktop rendering, and mobile, while episode types also appear in the player. apps/mobile/App.tsx is 7,126 lines, VideoPlayer.tsx is 3,814, and PluginDiscover.tsx is 2,242.

Problem. Data transport, normalization, orchestration, and rendering have no single owner. Optional-heavy parallel models force callers to cast after checks that the type system cannot retain, and giant components make simple state transitions depend on distant closures and refs.

Why it matters. This is where idiomatic TypeScript starts to resemble annotated scripting: the types follow the implementation instead of shaping it. Changes to cast, metadata, playback, or profile state must be repeated across layers and are easy to make inconsistently.

Quick win. Establish one canonical wire DTO per boundary, map it once into discriminated application models, and split mobile connection, library, and playback orchestration into focused controllers or hooks. Treat assertion count as a signal, not a deletion quota. Effort: Large. Accept when each model has one owner and renderer components consume already-narrowed values.
Needs verification
3

Suppressed effect dependencies may hide stale lifecycle state.

React lifecycleNeeds verification

Evidence. Twelve react-hooks/exhaustive-deps suppressions remain, eleven in apps/mobile/App.tsx. They cover saved-session restore, reconnect cadence, health checks, playback initialization, gesture handlers, and track selection.

Risk. The comments explain intent, but static review cannot prove each closure remains fresh across reconnects, profile changes, backgrounding, stream changes, or player replacement.

Why verify. These effects coordinate the most timing-sensitive parts of the product. A stale callback can present as intermittent offline state, duplicate retries, incorrect resume position, or track choices that only fail after a sequence of state changes.

Recommendation. Extract the connection and playback state machines first, replace suppression with stable callbacks or explicit event inputs, then test lifecycle transitions with fake timers and deterministic state sequences. No runtime tests were executed for this report.
Working well to preserve
1

The compiler and lint baseline rejects the easiest escapes.

Type disciplineWorking well

Evidence. Desktop and mobile enable strict. ESLint rejects explicit any; desktop also rejects non-null assertions. AST inspection found zero explicit any keywords and zero non-null assertions in production desktop and mobile TypeScript.

Why it works. The codebase already prefers unknown, type guards, optional chaining, and inference over broad unsafe annotations. This keeps local implementation errors visible to the compiler.

What to preserve. Keep these rules as errors and extend the same policy to every TypeScript package. Do not solve boundary work by introducing any or global casting wrappers.

5

Several critical paths already demonstrate the right pattern.

Error preventionWorking well

Evidence. databasePluginRepository.ts parses to unknown, checks records, validates identifiers and states, and returns normalized values. Fingerprint decoding validates frame arrays and numeric fields before narrowing. safeFetch.ts constrains hosts, redirects, response sizes, and addresses, while IPC sender identity is checked centrally.

Why it works. These modules keep runtime validation close to the boundary and convert malformed input into specific failures before domain logic runs.

What to preserve. Reuse this parse, validate, normalize pattern for provider payloads, session storage, SQLite JSON columns, and IPC arguments rather than adding a new validation abstraction with hidden control flow.

What works well

Strictness is real, not cosmetic.

There is no explicit any or non-null assertion in production desktop and mobile TypeScript.

Primary issue

Runtime data receives compile-time trust.

Remote, persisted, and IPC values are often cast before their structure is proven.

Recommended action

Decode once, then model once.

Validate at boundaries, establish canonical DTO ownership, and split orchestration from rendering.

Expected outcome

Fewer distant failures and safer changes.

Provider drift, storage corruption, and lifecycle races become local, named, testable failures.

03 · Decision memo

Trust data only after decoding.
Make ownership visible in the types.

The shortest path to 9.0 is to standardize the validation pattern that already exists in the strongest security modules, then reduce the ownership sprawl that produces casts and hook suppressions. This pass does not recommend a framework rewrite. Runtime performance, UI accessibility, and package vulnerabilities are deferred because they were not evaluated here.
