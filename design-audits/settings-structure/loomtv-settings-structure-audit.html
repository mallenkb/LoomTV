UX / UI Audit · Loom Media Server Settings

Polished settings, but the structure is doing too much work

The biggest gap is information architecture: six equal tabs hide a Library catch-all that mixes sources, navigation, scanning, automation, and device data. The screen can reach the 9.0 benchmark by reorganizing around user goals while preserving its strong visual system.

Improvements
1The flat tab bar does not communicate the settings modelIn scopeImprovement
Category: IA. Evidence: Library, Playback, Network, Metadata API Keys, Theme, and About are presented as six equal peers in one horizontal strip. Problem: the labels mix user goals, implementation terms, and informational content. Why it matters: people must learn the product's internal taxonomy, and the strip has little room to scale.
Fix: use a secondary settings index grouped around goals: Library; Player; Sharing & Devices; Metadata & Subtitles; Appearance; App & Data. On desktop, a compact vertical index will scale better than another long horizontal control. Effort: Medium.
2“Library” is a catch-all, not one coherent taskIn scopeImprovement
Category: UX / IA. Evidence: the Library view begins with folder sources, then switches to “Sidebar Order”; further in the same captured flow it continues into scanning, automatic sync, backup, and clear-data controls. Problem: setup, navigation customization, routine maintenance, and destructive administration share one long page. Why it matters: frequent actions are buried and risky actions inherit the visual context of routine library work.
Fix: keep Folders and Scan & Sync in Library; move Sidebar Order to Appearance or Navigation; move Backup and Clear Data to App & Data behind a clearly labeled danger zone. Acceptance: each page should answer one user question in under five seconds.
3Repeated primary buttons flatten action priorityIn scopeImprovement
Category: UI / Interaction. Evidence: four bright yellow “Add” buttons repeat down the Library Folders card while each row is already visually distinct. Problem: every source category asks for first-glance attention. Why it matters: the primary color stops signaling the single best next action and increases visual noise.
Fix: use a single “Add folder” primary action that opens a media-type choice, or reduce row actions to quiet secondary buttons until the row is focused or hovered. Keep yellow for the page's main action. Effort: Small.
4Folder removal is too small and too implicitIn scopeImprovement
Category: Accessibility / Interaction. Evidence: each folder row ends with a small red “×” icon without visible text. Problem: the destructive target is easy to miss, its meaning depends on icon recognition, and its visible size appears below a comfortable pointer target. Why it matters: users can misread or mis-click a destructive control; keyboard focus and accessible naming cannot be confirmed from the screenshot alone.
Fix: provide a 44×44 minimum hit area, visible tooltip or “Remove” label, confirmation that names the folder, and an accessible name such as “Remove Movies folder.” Verify focus, keyboard activation, and screen-reader output in implementation.
5Labels drift between user language and system languageIn scopeImprovement
Category: Copy. Evidence: visible labels include “Metadata API Keys,” “Anime / Animations,” “Others,” “Sidebar Order,” and the status “Available Folder is available.” Problem: the first label is implementation-led, category names are inconsistent with the main sidebar, and the status repeats itself. Why it matters: uneven terminology slows scanning and makes the product feel more technical than the task requires.
Fix: replace “Metadata API Keys” with “Metadata & Subtitles”; “Anime / Animations” with “Anime”; “Others” with “Other Media”; “Sidebar Order” with “Library navigation”; and “Available Folder is available.” with “Available · Folder connected.” Expected result: faster recognition and a calmer tone.

Recommendation · Path to 9.0

Reorganize by user goal, then tighten the action hierarchy

The shortest credible path is a structural pass, not a visual redesign. Keep the dark surfaces, yellow accent, clear cards, and inline health states. Change where controls live, rename the technical categories, and make destructive actions explicit. The result should feel like the same product with a clearer mental model.
