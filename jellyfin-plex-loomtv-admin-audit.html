Admin surfaces · Comparative audit

Jellyfin and Plex expose the server. LoomTV exposes the work.

LoomTV already has the pieces a private media server needs: libraries, metadata controls, local sharing, accounts, backups, logs, and a headless admin page. Jellyfin puts more of that information in one dashboard. Plex adds a mature setup and operations model, but also asks the user to sign in to a Plex account. The recommendation is to give LoomTV one calm server overview without copying either product's account or remote-access assumptions.

Product model findings
6

Plex's setup is polished, but its account requirement is the wrong default for LoomTV.

Mental modelMediumInferred

Evidence. Plex's Basic Setup Wizard starts with Plex account sign-in, then server name, optional outside-home access, and libraries. The local Plex review reached a sign-in gate. LoomTV's agreed model is private, local-first, and usable without a subscription or hosted account.

Problem. Copying Plex's account step would add a service dependency before the owner can reach local media.

Why it matters. LoomTV's strongest promise is ownership of the server and data. The first screen should reinforce that promise.

Recommendation. Keep the four-step LoomTV setup. Use the trusted desktop channel locally and normal account authentication headlessly. Offer remote access as an explicit network decision, not as an account requirement.

7

LoomTV's explicit metadata keys are honest, but heavier than the references' provider model.

Setup clarityMediumInferred

Evidence. LoomTV's Metadata API Keys card names TMDB, OMDb, Fanart, TVDB, TVmaze, and Jikan, and says TVmaze and Jikan need no keys. Jellyfin uses metadata providers through plugins and configuration. Plex uses agents and library metadata settings. Both hide most provider credentials in the provider configuration layer.

Problem. A new LoomTV owner can interpret the key list as a prerequisite even though the agreed fallback chain can work without keys.

Why it matters. The metadata step should help an owner finish setup, not make an optional integration look mandatory.

Recommendation. Keep all provider controls in Settings, but make onboarding say "Optional. TVmaze is the default when no key is available." Show fallback order and provider test results inline.

8

Remote access is a product decision, not a missing toggle.

Trust and controlMediumNeeds verification

Evidence. Plex's documented setup offers "Allow me to access my media outside my home" and its Remote Access page manages port mapping and connection status. Jellyfin has a Networking area. LoomTV currently supports local sharing, pairing, TLS-backed administration, and connecting to another shared library. The broader internet-facing remote-access flow was not tested here.

Risk. A rushed parity feature could expose a private server or make port changes confusing.

Why verify. The right LoomTV design depends on the security model and deployment target. It should not be inferred from Plex's account-led flow.

Recommendation. Validate the local network and TLS flow first. If internet remote access is added, give it a dedicated explanation, explicit opt-in, connection status, and a clear revoke path.

The admin surfaces need a real interaction and accessibility pass.

Accessibility and recoveryMediumNeeds verification

Evidence. The Jellyfin DOM exposes named links and buttons. LoomTV's headless HTML uses labelled navigation, forms, dialogs, alerts, and controls in source. This review did not run keyboard navigation, focus order, zoom, screen readers, responsive reflow, or failure recovery.

Audit goal

Compare the admin experience.

Find the smallest LoomTV changes that close the useful gaps without copying Plex's hosted-account model or Jellyfin's full feature scope.

Primary user and task

Owner keeping a private server healthy.

Scope and evidence

Jellyfin 10.11.11 was inspected locally. Plex was checked locally through its sign-in gate and its official setup, network, dashboard, library, logs, and scheduled-task docs. LoomTV source and an isolated desktop-hosted server state were inspected.

Success and confidence

Answer the next server question fast.

Medium confidence. Validate the proposed overview with task time to find scan state, active sessions, recent errors, and library counts.

What works well

LoomTV already has a coherent private-server base.

Its four-step setup, library folders, metadata fallbacks, local sharing, server administration link, backups, logs, and sessions are the right building blocks.

Primary issue

The owner has no single status view.

Jellyfin makes the server state obvious in one dashboard. LoomTV makes the owner assemble it from Settings and the headless admin page.

Recommended action

Add one read-only overview, then link out.

Show health, library counts, scan state, active sessions, recent activity, and the next action. Reuse existing APIs and controls instead of creating a second admin system.

Expected outcome

Faster diagnosis without a heavier product.

Owners can answer "is my server healthy?" and "what should I do next?" before opening Library, Network, Metadata, or Logs.

04 · Decision memo

Make the existing LoomTV server easier to read before making it bigger.

Jellyfin's dashboard is the useful pattern to borrow. Plex's documentation is the useful warning about scope. LoomTV should add a read-only overview, keep local ownership first, and make the existing work easier to find.
