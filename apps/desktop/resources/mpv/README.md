# Bundled MPV staging

This directory contains the staged macOS arm64 MPV payload used by packaged
desktop releases. Other target payloads must be supplied separately and staged
under:

```text
resources/mpv/<platform>/<arch>/
  mpv | mpv.exe
  <required runtime libraries and support files>
  runtime-manifest.json       # generated by LoomTV staging
```

Use the target names used by the packager (`darwin`, `win32`, or `linux`) and
the target architecture (`arm64`, `x64`, `ia32`, or `arm`). Keep native files
outside `app.asar`. The staging script generates a `runtime-manifest.json`
with SHA-256 entries. The packaged-runtime verifier checks the selected
payload, its executable file format and POSIX execute bit, and those manifest
entries. A manifest contains `manifestVersion: 1`,
`platform`, `architecture`, and a `files` array (or path-to-hash object); each
file entry may provide a 64-character hexadecimal `sha256` value.

The current macOS arm64 payload is the official mpv 0.41.0 macOS 14 arm
release. Its archive SHA-256 is
`5c96f9b21355fc0a11d2e2161ad65f33031070e9fb3f6bd9865fb459b94587e6` and its
source release is <https://github.com/mpv-player/mpv/releases/tag/v0.41.0>.
The target staging manifest records SHA-256 values for the files copied into
the application resources. Do not download, build, or execute a native
runtime from the LoomTV application at runtime.

For local desktop files LoomTV uses bundled or otherwise available MPV for the
classic integrated player composition after LibVLC. LibVLC uses an in-window
NSView host on macOS and an HWND child host on Windows. If MPV is unavailable,
LoomTV uses its Chromium/HLS fallback. Remote and LAN
playback remain under the authenticated LoomTV server/direct-play/transcode
path; bundling MPV does not change that authority.
