# Startup timings and code caches

Normal primary launches write `startup-timings.json` in Electron's `userData` directory. The file retains ten launches, including incomplete launches. Each launch has a process start timestamp from `performance.timeOrigin` and millisecond offsets for process start, app ready, media server ready, window creation, the first native show event, renderer DOM content loaded, and the first library render. The renderer sends its timestamp through sender-validated IPC after the library splash is removed and animation frames allow the layout to paint. Onboarding and the profile gate do not count as a library render.

`windowToLibraryMs` is `firstLibraryRender - windowRevealed`. Inspect that field in the most recent complete launch to compare the reveal-to-library gap. Writes are coalesced and asynchronous, with an atomic replacement and a bounded history read. They do not depend on `LOOMTV_DEBUG_PLAYBACK`. An abrupt termination before a pending write finishes can lose the newest marks.

The small `.vite/build/main.js` entry resolves `LOOMTV_DATA_DIR`, including trimmed relative overrides, before loading application modules. The default remains `<appData>/LoomTV`. It enables the Node module compile cache at `<userData>/v8-compile-cache`, then requires `.vite/build/main-bundle.js`. Both files remain inside asar with the existing Forge and electron-builder include rules. Cache writes go to userData. Node caches modules loaded after enablement and treats cache failure as an optimization failure. See the [Node version bundled with Electron 43.1.1](https://raw.githubusercontent.com/electron/electron/v43.1.1/DEPS) and its [module cache documentation](https://raw.githubusercontent.com/nodejs/node/v24.18.0/doc/api/module.md).

Electron 43.1.1 documents `codeCache` for standard privileged schemes. Its Chromium patch permits the HTTP, WebUI, and explicitly registered code-cache schemes in the persistent script cache; `file://` is outside that path. The packaged renderer now loads from `loomtv://app/index.html`, with its assets confined to the built renderer directory. The existing media hosts and `plexserver` alias keep their handlers. CSP remains enforced, the renderer remains sandboxed, and IPC and navigation checks compare the exact application host and document. See the [Electron 43 scheme options](https://raw.githubusercontent.com/electron/electron/v43.1.1/docs/api/structures/custom-scheme.md), [scheme registration source](https://raw.githubusercontent.com/electron/electron/v43.1.1/shell/browser/api/electron_api_protocol.cc), and [Chromium code-cache patch](https://raw.githubusercontent.com/electron/electron/v43.1.1/patches/chromium/feat_allow_code_cache_in_custom_schemes.patch).

The scheme change creates a new browser storage origin. A one-time migration copies bounded Loom localStorage preferences without overwriting values on the new origin. Hidden migration documents have page scripts disabled and no IPC preload. Only explicit storage scripts execute in an isolated world. Chromium's [script execution policy](https://raw.githubusercontent.com/chromium/chromium/150.0.7871.114/third_party/blink/renderer/core/frame/local_frame.cc) permits that isolated-world execution with page scripts disabled. sessionStorage credentials are not copied. The migration marker skips this work on later launches.

Main does not cache projected detail responses. Earlier branch work already routes `desktopApi.getLibraryItem` through the renderer query cache, and detail hydration uses the same read. Detail results now have fifteen-second freshness and idle retention, with the existing 24-entry family cap and 8 MiB overall inactive-result budget. Prefetch permits three concurrent distinct items and deduplicates repeated hovers. Catalog revision, profile, session, and accepted legacy catalog replacements invalidate old results.

No startup latency or cache-hit measurements were taken here. A minimal Electron runtime fixture aborted with `SIGABRT` before application code ran. Production cache persistence inside asar, actual renderer cache hits, visual behavior, storage migration in Chromium, and the reveal-to-library gap still need a live packaged run. The production main build and verifier pass. No static first-paint shell was added.
