Findings brief · LoomTV admin experience

What Jellyfin and Plex make obvious, and what LoomTV should do next

This is the short version of the comparative audit. Jellyfin has the clearest server dashboard. Plex has the broadest documented operations model, but it also brings a hosted-account dependency. LoomTV already has the right private, video-first building blocks. The main gap is where they are presented.

Findings

The findings are grouped by what should change, what should remain deliberate, and what still needs a real interaction check.

Act on

1. LoomTV's admin state is split across surfaces.

Medium

Observed. Jellyfin puts server details, scan controls, library counts, devices, activity, and paths on one dashboard. LoomTV has equivalent pieces in desktop Settings and the headless admin page.

Why it matters. An owner has to remember where each answer lives, especially when something is broken.

Do. Add a read-only owner overview that links to the existing pages and APIs.

2. LoomTV has useful operational data, but it is not gathered at the first stop.

Medium

Observed. Jellyfin shows devices and recent activity. Plex documents Dashboard, Alerts, Conversions, bandwidth, logs, and scheduled maintenance. LoomTV already has sessions, logs, backups, scans, and server status in its headless admin.

Why it matters. Recent events are what owners need when playback, scanning, or access fails.

Do. Add Recent activity and Server work cards to the overview. Link each item to the existing detail page.

3. LoomTV should explain optional metadata without making keys feel required.

Medium

Observed. LoomTV names TMDB, OMDb, Fanart, TVDB, TVmaze, and Jikan in its Metadata API Keys settings. TVmaze and Jikan work without keys. Jellyfin and Plex place most provider configuration inside their provider or agent model.

Why it matters. A new owner may stop at an optional step or assume metadata will not work without credentials.

Do. Say “Optional. TVmaze is the default when no key is available.” Show the fallback order and provider result inline.

4. Scope is a product choice, not a checklist.

Medium

Observed. Jellyfin and Plex expose more categories, including networking, live TV and DVR, scheduled tasks, and advanced operations. LoomTV is intentionally focused on video and already has a smaller set of working controls.

Why it matters. Adding empty parity sections would make LoomTV harder to understand and imply unfinished support.

Do. Add the overview now. Keep Live TV/DVR, a scheduler, and broader internet remote access as labelled roadmap items until their contracts are real.

Keep deliberate

5. Jellyfin's server summary is worth borrowing.

Working well

Observed. Server name and versions appear above Scan All Libraries, Restart, Shutdown, and library counts.

Why it works. The owner can identify the server and take a safe next action without browsing the settings tree.

Keep. LoomTV's direct scan, backup, server, and library controls. Put links to them in the new overview instead of duplicating their logic.

6. LoomTV's local-first setup is the right contrast to Plex.

Working well

Observed. Plex's setup starts with Plex account sign-in and offers an outside-home access choice. LoomTV's agreed flow is private, local-first, and does not require a hosted subscription.

Why it works. The first LoomTV screen reinforces ownership of the server and its data.

Keep. The four-step setup, trusted desktop channel, normal headless authentication, and explicit opt-in for any future internet remote access.

Verify before calling it finished

7. Remote access needs its own security decision.

Needs verification

Observed. Plex documents port mapping and connection status. Jellyfin has a Networking area. LoomTV has LAN sharing, pairing, and TLS-backed administration. The broader internet-facing flow was not tested in this audit.

Risk. Copying a remote-access toggle without a clear revoke path could expose a private server or make port changes confusing.

Verify. Test local network and TLS first. If internet access is added, make it opt-in, show connection state, and provide a clear revoke path.

8. Admin accessibility and failure recovery are not proven by the screenshots.

Needs verification

Observed. Jellyfin exposes named links and buttons in the inspected DOM. LoomTV's headless HTML includes labelled navigation, forms, dialogs, alerts, and controls. Keyboard order, zoom, screen readers, responsive reflow, and failure recovery were not exercised.

Risk. A visual match can still fail on a bad folder path, expired session, failed scan, or rejected provider key.

Verify. Run keyboard-only setup, folder failure, scan retry, session expiry, provider rejection, focus, and 200% zoom checks on both `/app` and `/admin`.

Recommended order

These actions use LoomTV's existing state and controls. They should land before a larger admin expansion.

1

Build the server overview

Health, server identity, library counts, scan progress, active sessions, recent activity, and the next action.

2

Link, do not duplicate

Open Library, Network, Metadata, Sessions, Logs, Users, and Backups from the overview.

3

Make optional choices explicit

Explain metadata fallback and remote access in plain language. Show retry and revoke paths.

4

Run the interaction gate

Verify setup errors, scan retry, session expiry, keyboard use, focus, responsive layout, and 200% zoom.

Evidence and limits

The findings are strong enough to choose the next work, but not to claim product parity or accessibility compliance.

Inspected

  • Jellyfin 10.11.11 local dashboard, including navigation, server summary, counts, devices, activity, and paths.
  • Plex local web entry point, which stopped at its sign-in gate. No Plex credentials were entered.
  • Official Plex setup, dashboard, network, remote access, library, logs, and scheduled-task documentation.
  • LoomTV desktop Settings, headless `/admin`, setup state, library controls, metadata settings, network administration, sessions, logs, backups, and users.

Not proven

  • Plex admin screens after sign-in.
  • Keyboard, screen-reader, focus, zoom, responsive, or error-recovery behaviour.
  • Internet remote access, physical NAS behaviour, casting receivers, or playback performance.
  • User outcomes, support volume, or task-time improvements.
